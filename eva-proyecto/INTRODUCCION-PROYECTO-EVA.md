# INTRODUCCIÓN AL PROYECTO EVA

## Sistema de Gestión Integral para Equipos Biomédicos

---

## 1. PROPÓSITO DEL PROYECTO

El **Proyecto EVA** (Equipos y Vidas Aseguradas) es una solución tecnológica integral diseñada para revolucionar la gestión de equipos biomédicos en instituciones de salud. Este sistema web moderno surge como respuesta a la necesidad crítica de digitalizar, centralizar y optimizar todos los procesos relacionados con el manejo de tecnología médica hospitalaria.

### Objetivo Principal

Proporcionar una plataforma digital completa que permita a las instituciones de salud gestionar de manera eficiente el ciclo de vida completo de sus equipos biomédicos, desde la adquisición hasta la disposición final, garantizando la trazabilidad, seguridad y cumplimiento normativo en cada etapa.

### Visión Estratégica

Convertirse en la herramienta estándar para la gestión de equipos biomédicos en el sector salud, contribuyendo a mejorar la calidad de la atención médica mediante la optimización de los recursos tecnológicos hospitalarios.

## 2. PROBLEMÁTICA IDENTIFICADA

### 2.1 Problemas Operacionales Actuales

#### **Gestión Manual y Fragmentada**

- Registro en papel o hojas de cálculo dispersas
- Pérdida de información crítica por falta de centralización
- Dificultad para acceder a historiales completos de equipos
- Procesos lentos y propensos a errores humanos

#### **Falta de Trazabilidad**

- Imposibilidad de rastrear el historial completo de un equipo
- Ausencia de registros de mantenimientos preventivos y correctivos
- Pérdida de documentación técnica y certificaciones
- Dificultad para generar reportes de gestión

#### **Cumplimiento Normativo Deficiente**

- Incumplimiento de regulaciones sanitarias por falta de documentación
- Ausencia de calendarios de calibración y mantenimiento
- Dificultad para demostrar cumplimiento en auditorías
- Riesgos legales por inadecuada gestión documental

#### **Ineficiencia en la Toma de Decisiones**

- Falta de información en tiempo real sobre el estado de equipos
- Dificultad para planificar presupuestos de mantenimiento
- Ausencia de métricas de rendimiento y disponibilidad
- Incapacidad para optimizar la distribución de recursos

### 2.2 Impacto en la Atención Médica

#### **Riesgos para Pacientes**

- Equipos no calibrados o con mantenimiento vencido
- Fallas no documentadas que pueden repetirse
- Ausencia de protocolos de seguridad actualizados
- Tiempo de inactividad no planificado de equipos críticos

#### **Costos Operacionales Elevados**

- Mantenimientos reactivos más costosos que preventivos
- Duplicación de esfuerzos por falta de información centralizada
- Pérdida de tiempo en búsqueda de documentación
- Sanciones por incumplimiento normativo

## 7. LIMITACIONES Y EXCLUSIONES DEL ALCANCE

### 7.1 Funcionalidades No Incluidas

#### **Gestión Financiera Completa**

- **Contabilidad integral**: El sistema no reemplaza software contable especializado
- **Facturación automática**: No genera facturas ni maneja cuentas por cobrar/pagar
- **Presupuestos detallados**: Limitado a estimaciones básicas de mantenimiento
- **Control de inventarios de repuestos**: No maneja stock detallado de componentes

#### **Gestión de Recursos Humanos**

- **Nómina de técnicos**: No incluye procesamiento de salarios
- **Evaluación de desempeño**: No tiene módulos de RRHH especializados
- **Capacitación formal**: Registra pero no gestiona programas de formación
- **Certificaciones profesionales**: Solo almacena, no valida competencias

#### **Integración con Equipos IoT**

- **Monitoreo en tiempo real**: No conecta directamente con sensores de equipos
- **Telemetría automática**: No captura datos automáticos de funcionamiento
- **Alertas de hardware**: Depende de reportes manuales, no automáticos
- **Diagnósticos remotos**: No incluye capacidades de diagnóstico a distancia

#### **Gestión Hospitalaria General**

- **Historia clínica**: No maneja información de pacientes
- **Programación de cirugías**: No gestiona calendarios quirúrgicos
- **Gestión de camas**: No incluye disponibilidad hospitalaria
- **Farmacia**: No maneja inventarios de medicamentos

### 7.2 Limitaciones Técnicas

#### **Capacidades de Procesamiento**

- **Análisis de Big Data**: Limitado a reportes estándar, no análisis masivos
- **Inteligencia Artificial**: No incluye algoritmos de ML o predicción avanzada
- **Procesamiento de imágenes**: No analiza radiografías o imágenes médicas
- **Reconocimiento automático**: No lee códigos de barras o QR automáticamente

#### **Integraciones Externas**

- **ERP empresariales**: Integración limitada con SAP, Oracle u otros
- **Sistemas de terceros**: API disponible pero requiere desarrollo adicional
- **Plataformas de cloud**: Diseñado para instalación local principalmente
- **Sistemas legacy**: Compatibilidad limitada con sistemas muy antiguos

#### **Funcionalidades Móviles**

- **App nativa**: Solo interfaz web responsive, no aplicación móvil nativa
- **Trabajo offline**: Requiere conexión a internet para todas las funciones
- **Sincronización móvil**: No maneja datos sin conexión
- **Notificaciones push**: Limitadas a navegador web

### 7.3 Exclusiones de Responsabilidad

#### **Cumplimiento Normativo Específico**

- **Regulaciones internacionales**: Enfocado en normativas locales/nacionales
- **Estándares de otros países**: No garantiza cumplimiento fuera del contexto local
- **Cambios normativos futuros**: Requiere actualizaciones para nuevas regulaciones
- **Interpretación legal**: No proporciona asesoría jurídica especializada

#### **Soporte Técnico Especializado**

- **Reparación de equipos**: No incluye servicios técnicos de reparación
- **Consultoría biomédica**: No proporciona asesoría técnica especializada
- **Validación metrológica**: No realiza calibraciones físicas de equipos
- **Auditorías externas**: No conduce auditorías regulatorias oficiales

#### **Personalización Avanzada**

- **Desarrollos a medida**: Funcionalidades específicas requieren desarrollo adicional
- **Interfaces personalizadas**: Limitado a configuraciones predefinidas
- **Reportes complejos**: Reportes muy específicos pueden requerir desarrollo
- **Integraciones únicas**: Conexiones especiales requieren trabajo adicional

### 7.4 Consideraciones de Implementación

#### **Migración de Datos**

- **Sistemas complejos**: Migración desde sistemas muy especializados puede ser limitada
- **Formatos propietarios**: No garantiza importación de todos los formatos
- **Validación histórica**: Datos antiguos pueden requerir revisión manual
- **Limpieza de datos**: Proceso de depuración puede ser necesario

#### **Capacitación y Adopción**

- **Entrenamiento básico**: Incluye capacitación estándar, no especializada
- **Cambio organizacional**: No incluye consultoría de gestión del cambio
- **Soporte post-implementación**: Limitado a soporte técnico estándar
- **Certificación de usuarios**: No emite certificaciones oficiales de competencia

#### **Escalabilidad Específica**

- **Instituciones multi-sede**: Funcionalidad básica, puede requerir configuración adicional
- **Redes hospitalarias**: Gestión centralizada limitada para múltiples hospitales
- **Franquicias médicas**: No diseñado específicamente para cadenas comerciales

## 8. REQUERIMIENTOS FUNCIONALES Y NO FUNCIONALES

### 8.1 Requerimientos Funcionales

#### **RF-01: Gestión de Usuarios y Autenticación**

- **RF-01.1**: El sistema debe permitir el registro de usuarios con diferentes roles
- **RF-01.2**: Debe autenticar usuarios mediante email y contraseña
- **RF-01.3**: Debe mantener sesiones activas por tiempo configurable
- **RF-01.4**: Debe permitir recuperación de contraseñas
- **RF-01.5**: Debe registrar audit trail de acciones de usuarios

#### **RF-02: Gestión de Equipos Biomédicos**

- **RF-02.1**: Debe permitir registro completo de equipos con todos sus datos técnicos
- **RF-02.2**: Debe clasificar equipos por categorías (biomédico, industrial, tecnológico)
- **RF-02.3**: Debe gestionar estados de equipos (activo, inactivo, mantenimiento, baja)
- **RF-02.4**: Debe permitir búsqueda y filtrado avanzado de equipos
- **RF-02.5**: Debe generar códigos únicos de identificación automáticamente
- **RF-02.6**: Debe permitir asignación de ubicaciones y responsables

#### **RF-03: Gestión Documental**

- **RF-03.1**: Debe almacenar y organizar 30 tipos diferentes de documentos
- **RF-03.2**: Debe permitir carga múltiple de archivos (PDF, imágenes, documentos)
- **RF-03.3**: Debe permitir compartir documentos entre múltiples equipos
- **RF-03.4**: Debe generar previsualizaciones de documentos PDF
- **RF-03.5**: Debe mantener historial de versiones de documentos
- **RF-03.6**: Debe permitir descarga y visualización de documentos

#### **RF-04: Programación de Mantenimientos**

- **RF-04.1**: Debe programar mantenimientos preventivos automáticamente
- **RF-04.2**: Debe registrar mantenimientos correctivos realizados
- **RF-04.3**: Debe generar calendarios de mantenimiento
- **RF-04.4**: Debe enviar notificaciones de mantenimientos pendientes
- **RF-04.5**: Debe registrar técnicos responsables y procedimientos

#### **RF-05: Reportes y Consultas**

- **RF-05.1**: Debe generar reportes de estado de equipos
- **RF-05.2**: Debe crear dashboards con métricas en tiempo real
- **RF-05.3**: Debe exportar datos en formatos Excel y PDF
- **RF-05.4**: Debe generar reportes de cumplimiento normativo
- **RF-05.5**: Debe mostrar estadísticas de mantenimiento y disponibilidad

#### **RF-06: Integración con INVIMA**

- **RF-06.1**: Debe verificar registros sanitarios automáticamente
- **RF-06.2**: Debe validar equipos contra base de datos INVIMA
- **RF-06.3**: Debe mostrar estado de registro sanitario en tiempo real
- **RF-06.4**: Debe alertar sobre vencimientos de registros

### 8.2 Requerimientos No Funcionales

#### **RNF-01: Rendimiento**

- **RNF-01.1**: Tiempo de respuesta máximo de 3 segundos para consultas simples
- **RNF-01.2**: Tiempo de respuesta máximo de 5 segundos para reportes complejos
- **RNF-01.3**: Capacidad para gestionar hasta 100,000 equipos simultáneamente
- **RNF-01.4**: Soporte para hasta 500 usuarios concurrentes
- **RNF-01.5**: Tiempo de carga inicial de la aplicación menor a 10 segundos

#### **RNF-02: Disponibilidad y Confiabilidad**

- **RNF-02.1**: Disponibilidad del sistema del 99.5% mensual
- **RNF-02.2**: Tiempo máximo de inactividad planificada de 4 horas mensuales
- **RNF-02.3**: Recovery Time Objective (RTO) de 4 horas
- **RNF-02.4**: Recovery Point Objective (RPO) de 1 hora
- **RNF-02.5**: Respaldos automáticos diarios de la base de datos

#### **RNF-03: Seguridad**

- **RNF-03.1**: Encriptación SSL/TLS para todas las comunicaciones
- **RNF-03.2**: Encriptación de contraseñas con algoritmos seguros (bcrypt)
- **RNF-03.3**: Control de acceso basado en roles (RBAC)
- **RNF-03.4**: Registro completo de auditoría de todas las acciones
- **RNF-03.5**: Validación y sanitización de todas las entradas de usuario
- **RNF-03.6**: Protección contra ataques CSRF, XSS y SQL Injection

#### **RNF-04: Usabilidad**

- **RNF-04.1**: Interfaz intuitiva que requiera máximo 2 horas de capacitación
- **RNF-04.2**: Diseño responsive compatible con dispositivos móviles y tablets
- **RNF-04.3**: Compatibilidad con navegadores modernos (Chrome, Firefox, Edge, Safari)
- **RNF-04.4**: Mensajes de error claros y orientación al usuario
- **RNF-04.5**: Funciones de búsqueda y filtrado en tiempo real

#### **RNF-05: Escalabilidad**

- **RNF-05.1**: Arquitectura que permita escalamiento horizontal
- **RNF-05.2**: Base de datos optimizada para crecimiento de datos
- **RNF-05.3**: Capacidad de agregar nuevos módulos sin afectar funcionalidad existente
- **RNF-05.4**: Soporte para múltiples instituciones en una sola instalación
- **RNF-05.5**: API REST preparada para integraciones futuras

#### **RNF-06: Mantenibilidad**

- **RNF-06.1**: Código fuente documentado y siguiendo estándares de codificación
- **RNF-06.2**: Arquitectura modular que facilite actualizaciones
- **RNF-06.3**: Logs detallados para facilitar debugging

- **RNF-07.3**: Base de datos MySQL 8.0 o superior

- **RNF-08.3**: Integración con servicios web de terceros (INVIMA)

- **RNF-09.2**: Alineación con Decreto 4725 de 2005 sobre dispositivos médicos
- **RNF-09.3**: Cumplimiento con Ley 1581 de 2012 de Protección de Datos
